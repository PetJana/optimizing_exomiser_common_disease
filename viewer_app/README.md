# Gene Transcript Variant Viewer

An R Shiny app that plots variants as a lollipop diagram on top of a gene's
exon/transcript structure.

## What it does

- You pick a gene from the drop-down (the 62 genes cached in `transcripts.rds`).
- It draws the exon structure as a horizontal gene model, and plots variants
  as lollipops above it with **ggplot2** — one circle per carrier.
- Below the plot: a variant table, and per-gene biochemistry figures if a
  `figures/` folder is present (not generated by this repository).


## Setup

```r
install.packages(c("shiny", "bslib", "DT", "ggplot2"))
```

An earlier version drew the plot with Bioconductor's trackViewer (kept as
`app_trackViewer.R`), but it needed too much memory for shinyapps.io's free
tier. `prepare_transcripts.R` still needs biomaRt, but only to rebuild
`transcripts.rds` — the app itself doesn't.

## Run

```r
shiny::runApp("app.R")
```

## Swapping in real variant data

The app loads variant data from a single file for the current Exomiser
version:

```r
DEFAULT_VERSION_FILE <- "variants_exomiser_14.0.0.rds"
```

**Exomiser version:** currently fixed to 14.0.0 rather than a dropdown
choice — the version picker is commented out in `app.R` (both the UI
`selectInput` and the `EXOMISER_VERSION_FILES` mapping) since only one
version is in use right now. To bring it back, uncomment those two spots
and swap `DEFAULT_VERSION_FILE` for
`EXOMISER_VERSION_FILES[[input$exomiser_version]]` inside `variants_source()`.

**Quick path — use `prepare_variants.R`:** if your data is one row per
variant per carrier, edit the column names near the top of
`prepare_variants.R` to match your file, set `INPUT_FILE` and `OUTPUT_FILE`
(output must match `DEFAULT_VERSION_FILE` in `app.R`), then run:

```r
source("prepare_variants.R")
```

**Full control — edit `get_variants()` directly:** everything variant-related
flows through one function in `app.R`:

```r
get_variants <- function(gene_symbol, variants_list) { ... }
```

Point it at a VCF parser (e.g. `VariantAnnotation::readVcf`), a live
database/API call (e.g. ClinVar), or anything else — it just needs to keep
returning a data.frame with columns `pos`, `label`, `type`, `score`,
`carriers`.

**Either way:** positions must be **GRCh37/hg19**, matching the assembly the
transcript cache was built from — mismatched assemblies don't error, they
silently plot variants outside the visible exon range so nothing appears.

## Speeding up gene loading with a fixed gene list

`prepare_transcripts.R` pre-fetches their exon structure once and
caches it to `transcripts.rds`:

1. Edit the `GENES` list at the top of `prepare_transcripts.R`.
2. Run it: `source("prepare_transcripts.R")`.
3. `app.R` automatically loads `transcripts.rds`

Re-run the script any time you want to add genes or refresh the cache.

## Deploying it as a hosted link

`deploy.R` publishes the app to [shinyapps.io](https://www.shinyapps.io) (free tier):

1. Create a free shinyapps.io account.
2. In the dashboard: **Account → Tokens → Show → Show Secret**.
3. Paste those three values into `setAccountInfo()` near the top of `deploy.R`,
   uncomment that block, and run it once.
4. Comment that block back out, then run `deploy.R` again (or just
   `rsconnect::deployApp()`) whenever you want to redeploy.

The first deploy takes a while — shinyapps.io has to build `biomaRt`,
`trackViewer`, and `GenomicRanges` from Bioconductor, not just CRAN.
